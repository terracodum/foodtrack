# Развёртывание в своём ChatGPT Sites

Этот репозиторий — очищенный источник для нового проекта. В `.openai/hosting.json` нет project_id. Сначала прочитайте актуальный навык Sites; имена и расположение helpers могут обновляться.

## Порядок для агента

1. Подготовьте новый пустой каталог. Используйте исходники как sanitized template source через поддерживаемый `project-setup.mjs --template-source <absolute-source-directory>`; не создавайте новый starter поверх прикладных компонентов.
2. Создайте ровно один новый приватный Site в текущем аккаунте. Сохраните возвращённый project_id в manifest. Не используйте чужие идентификаторы, адреса, remote URL или базу.
3. Сохраните `d1: DB` и `r2: BUCKET`. Схема таблицы journals и миграция/metadata включены в `db/` и `drizzle/`. Sites применяет миграции при публикации; обработчики не создают таблицы во время запросов.
4. Используйте актуальные helpers установки, сборки, синхронизации и публикации из навыка Sites. Dependencies зафиксированы в pnpm-lock.yaml. Self-hosted entrypoint для Sites не используется.
5. Сохраните встроенную авторизацию getChatGPTUser и проверку пользователя на сервере для каждого API. DB записи и R2 файлы привязаны к site-scoped userId. Не открывайте публичный доступ ради работоспособности.
6. Проверьте первый вход, заполнение анкеты, создание, изменение и удаление тестовых записей, перезагрузку, отчёт InBody. Проверки preview используют отдельную тестовую базу; фиктивные записи в production не переносить.
7. Опубликуйте приватно только для нового владельца и дайте рабочую ссылку.

Не заменяйте D1/R2 localStorage, демонстрационным массивом или localhost. Если Sites недоступен в аккаунте, скажите об этом прямо и предложите документированный self-hosted запуск.

## Резервные копии

JSON экспортируется из настроек; оригиналы файлов скачиваются отдельно. При переносе в новый аккаунт и новую базу восстановятся показатели из JSON, но ссылки на R2-файлы прежнего аккаунта не дадут доступа к ним. Отчёты нужно прикрепить заново.

## Кастомизация

После первого запуска владелец может просить ChatGPT менять приложение по адресу своего нового Site. Обновления других экземпляров автоматически не применяются. Сначала сохраняйте резервные копии.
