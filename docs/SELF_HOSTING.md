# Самостоятельный запуск

## Устройство

React/Vite frontend и Node.js 24 HTTP server. Один экземпляр — один владелец с паролем; регистрация нескольких пользователей не реализована. SQLite находится в `DATA_DIR/foodtrack.sqlite`, оригиналы — в `DATA_DIR/reports`. Для standalone не нужны ChatGPT, Cloudflare, D1 или R2.

Сервер использует встроенный `node:sqlite`, поэтому нужна Node.js 24. Серверная сборка включает необходимые JS-зависимости, и runtime Docker-образ не устанавливает node_modules.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| FOODTRACK_PASSWORD | Обязательный пароль владельца, минимум 12 символов. Придумайте уникальный длинный пароль. |
| FOODTRACK_PASSWORD_FILE | Вместо переменной пароля можно указать файл с паролем; имеет приоритет. |
| PUBLIC_URL | Точный внешний адрес: схема, домен и порт. По умолчанию http://localhost:3000. |
| DATA_DIR | Постоянный каталог данных; по умолчанию ./data, в Docker — /data. |
| HOST | Адрес прослушивания, по умолчанию 0.0.0.0; для Node на том же хосте с proxy можно 127.0.0.1. |
| PORT | Порт процесса, по умолчанию 3000. |

`.env.example` не содержит готового пароля. Скопируйте в `.env` и заполните локально; реальный `.env` в Git не отправлять. Команда start:selfhost читает `.env`, если он существует. Docker Compose сам берёт `.env` и передаёт настройки процессу.

PUBLIC_URL нужен для проверки Origin. Если вход или сохранение дают 403, проверьте совпадение с адресом браузера. За HTTPS proxy задайте `https://ваш-домен`, тогда session cookie получит Secure. Не выставляйте HTTP вход с паролем в открытый интернет.

## Docker

```sh
cp .env.example .env
# Отредактируйте .env и задайте пароль.
docker compose up -d --build
```

По умолчанию порт опубликован на 127.0.0.1 сервера. Для внешнего доступа используйте HTTPS reverse proxy. Пример Caddyfile предназначен для Caddy на хосте, где localhost:3000 — приложение. В Docker-сети адрес upstream нужно адаптировать к имени сервиса, не копировать localhost слепо.

Обновление: сохраните резервную копию, получите новые исходники, выполните `docker compose up -d --build`. Именованный volume сохранится. Команда `docker compose down -v` удаляет его: без резервной копии восстановить данные нельзя.

## Node без Docker

```sh
pnpm install --frozen-lockfile
pnpm run build:selfhost
cp .env.example .env
# Отредактируйте .env.
pnpm run start:selfhost
```

Для постоянной работы запустите процесс через системный менеджер сервисов с нужным рабочим каталогом и DATA_DIR. Для безопасного публичного доступа нужен HTTPS reverse proxy.

## Резервные копии и восстановление

JSON из интерфейса переносит все записи, но не файлы. Полная копия — весь DATA_DIR, включая reports и SQLite-файлы.

Для простой согласованной копии остановите процесс, скопируйте DATA_DIR целиком, запустите снова. В Docker остановите сервис и скопируйте содержимое его volume (в том числе можно `docker compose cp foodtrack:/data ./foodtrack-backup`), затем запустите `docker compose start`. Храните копию вне каталога приложения и не публикуйте её в Git.

Для восстановления остановите процесс, верните DATA_DIR из копии и запустите с прежним или новым паролем. Смена настроенного пароля сбрасывает прежние сессии. Восстановление чужой базы даёт доступ к её содержимому: используйте только собственные копии.

## Модель доступа

Пароль проверяется scrypt, сессии случайные, в SQLite хранятся их хеши. Cookie — HttpOnly и SameSite=Strict; Secure включается при HTTPS PUBLIC_URL. Неавторизованные API отклоняются. Изменяющие запросы проверяют Origin. Вход ограничивает повторные неуспешные попытки по адресу соединения. Владелец сервера имеет технический доступ к диску — это не end-to-end encryption.

Статический интерфейс и иконки публичны, сами записи и файлы закрыты входом. Встроенные заголовки Sites сервер не принимает как авторизацию. Не используйте один экземпляр для независимых клиентов.

## Ограничения проверки

Сборки frontend/server и интеграционные тесты HTTP API выполнены на Node.js 24. Docker daemon в среде подготовки отсутствовал, поэтому Docker build/run не выдаются за проверенные. Внешний TLS proxy, установка PWA и камера телефона проверяются на вашем устройстве и домене.
