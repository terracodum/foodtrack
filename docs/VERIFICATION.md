# Проверки перед первым релизом

Проверено 31 октября 2026 года. Это результаты конкретных запусков; актуальный результат CI смотрите во вкладке Actions репозитория.

## Выполнено

- Установка зависимостей pnpm 11.25.0 с `--frozen-lockfile`.
- TypeScript: `tsc --noEmit --incremental false`.
- Production-сборки standalone client/server и Sites.
- Интеграционный тест standalone HTTP API на Node.js 24: авторизация, cookie, отказ запросам без входа и с поддельными заголовками Sites, Origin/CSRF, пустая первоначальная анкета, сохранение, конфликт версий, загрузка и скачивание файлов, запрет удаления используемого отчёта, gzip и сохранение данных/сессии после перезапуска.
- Docker-образ собран и тот же набор HTTP-проверок выполнен внутри контейнера, включая пересоздание контейнера с прежним тестовым volume. Локальная архитектура — `linux/arm64`. Временные контейнеры и volume удалены.
- Существующий приватный Site успешно обновлён до версии №6. При публикации все 162 файла исходного репозитория побайтово совпадали с checkout Sites; конфигурация размещения отличалась только `project_id`. Последующие изменения CI и документации публикуются в GitHub отдельно от Sites.
- В публичном manifest отсутствует `project_id`; runtime-каталоги, базы и файлы отчётов исключены из Git. Проверены распространённые признаки ключей, личные идентификаторы и локальные пути.
- Workflow публикации Docker по тегу проверен actionlint. Полный выпуск в GHCR выполняется при первом push тега версии.

## Пока не проверено

- Сборка и публикация обеих архитектур в GHCR через release workflow; для `linux/amd64` локальные runtime-проверки ещё не выполнялись.
- Создание нового Sites в аккаунте другого пользователя.
- Интерфейс и личный дневник в браузере после обновления Sites.
- Установка PWA, камера на конкретном телефоне, внешний домен и TLS proxy.

## Как повторить

```sh
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
pnpm run build:selfhost
pnpm run test:selfhost
pnpm run build
```

Для локальной проверки Docker: `docker build -t foodtrack:test .`. Используйте отдельные тестовые данные и пароль. Сборка образа сама по себе не проверяет его запуск.
